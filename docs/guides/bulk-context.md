# 多数のブックに AI の説明を付ける

この文書は、数百冊のブックに `pull --context` を1冊ずつ実行して分かったことをまとめたものです。
実行の前に決めておく設定、実行の進め方、止まったときの対処、処理に手間のかかるブックの形とこのツールの扱いを説明します。
各機能の仕様は、リンク先の文書を参照してください。

## 実行の前に決めておく設定

途中で止まらずに進めるため、次の設定を先に決めます。
設定ファイルの書き方は「[設定リファレンス](../reference/configuration.md#ai-生成の設定)」を参照してください。

| 設定 | 目安 | 理由 |
| --- | --- | --- |
| AI 接続先とモデル（generator） | 先に決めて変えない | 接続先、モデル、推論の強さ、出力の上限を変えると、それまでに作った説明が作り直しの対象になります。待ち時間の上限は含みません。 |
| `generation.limits.max_input_chars` | Codex CLI では `1000000` | 既定の `null` では、このツールは文字数を制限しません。Codex CLI は1回の入力が 1,048,576 文字を超えると送る前に断るため、根拠データが100万文字を超えるシートで止まります。数値を指定すると、超えるシートは長いデータの範囲を要約して送ります。補足文（`max_reference_chars`、既定 20000 文字）と指示文を足しても収まる値にします。 |
| `generation.limits.max_images` | `40` | 既定の24枚では、画面の切り抜きを並べたメモや、図形で描いた大きな図が収まらないことがあります。上限を超えるシートは写す範囲を広げて描き直しますが、文字が小さくなります（「[広い範囲を写して画像を減らす](sheet-content.md#広い範囲を写して画像を減らす)」）。 |
| generator の `overrides.timeout_seconds` | `1200` | 画像の多いシートでは、AI の応答に5分を超えることがあります。 |
| `generation.limits.max_render_seconds` | 既定の `600` | Excel の描画が、まれに応答しなくなります。上限を超えたシートは飛ばして次のシートへ進み、2回続けて超えるとそのブックを止めます。 |
| `generation.limits.max_workbook_mb` | 既定の `100` | Power Pivot のデータモデルで数百 MB になったブックは、Excel で開かずに文字だけで解析します（「[大きなブックを文字だけで解析する](sheet-content.md#大きなブックを文字だけで解析する)」）。 |

上限（`max_images`・`max_input_chars` など）は、再利用の判定に含みません。
途中で上限を変えても、作成済みの説明は作り直しません。
テンプレートを変えた場合は、AI を呼ばずに表示だけを作り直します（「[source 同期での更新と再利用](sheet-content.md#source-同期での更新と再利用)」）。

## 実行の進め方

### 少ない冊数で試す

最初に数冊から10冊ほどで試し、説明の質、時間、使用量を確かめます。
その前に `--dry-run` で、AI の呼び出し回数の予定、飛ばすシート、`duplicate-id`、ファイルサイズの上限を超えるブックを確かめます。
`--dry-run` は Excel の起動、AI の呼び出し、ファイルの保存を行いません。

時間と使用量は、シートの数と画像の枚数で大きく変わります。
次の値は目安です（AI の説明を付けた約570冊、Codex CLI の `gpt-6.1-sol`、推論 `high` の場合）。

| 項目 | 中央値 | 多いほうの1割 |
| --- | --- | --- |
| 1冊の時間 | 約3分 | 10分以上（最長は約46分） |
| 1冊の AI の呼び出し | 2回（1シートとブック要約） | 4回以上（最多は37回） |
| 1回の入力 | 約4万トークン | 7万トークン以上（20万トークンを超えることもある） |
| 1回の出力 | 約3千トークン | 6千トークン以上 |

### 1冊ずつ実行して結果を残す

ブックを指定して1冊ずつ `pull` を実行し、`--json` の結果を記録します。
ブックは、source の `workbooks.dir` からの相対パスか、絶対パスで指定します。

```shell
tkn-excel-note pull --source <id> "<ブックのパス>" --context --cover sheet --json
```

1冊ずつにすると、止めたときや失敗したときに影響がその1冊で済みます。
記録を見て成功したブックを飛ばせば、どこからでも再開できます。
`--cover sheet` を付けると、説明と同時に表紙の画像も作ります（「[シートの指定範囲を画像にする](catalog-operations.md#シートの指定範囲を画像にする)」）。

### 問題があれば止めて調べる

次の場合は、そのブックの後で実行を止め、原因を調べてから進めます。
ブックの形によっては、設定の変更やこのツールの修正が必要です（「[処理に手間のかかるブック](#処理に手間のかかるブック)」）。

- 結果の `status` が `success` 以外。
- 描くものがない空のシート以外のシートを `skipped` にした。
- 表紙の結果が `warning`。表紙を作れなくてもブックの結果は `success` になり、前の表紙が残るため、表紙の結果を別に確かめます。
- 想定と違うモデルで生成した（ログの `Generating sheet ... (provider=..., model=...)` で分かります）。

止めたブックは、原因を直した後に同じコマンドでやり直します。
生成済みのシートは再利用するため、AI を呼ぶのは残りのシートとブック要約だけです。

### 同時に別の pull を動かさない

同期の記録（`sync-state.json`）は、1つのファイルを読んで書き戻す作りで、ロックがありません。
一括実行の途中に、同じ記録を使う別の `pull` を動かすと、記録を上書きし合うおそれがあります。
途中で個別のブックを直す場合も、一括実行を止めてから行います。

### 中断と再開

代理ノートを書く前に止めたブックは、ノートも同期の記録も変わりません。
再開すると、そのブックを最初から処理します。

強制終了すると、処理中のノートのロック（`~/.tkn/excel_note/state/context/locks/`）が残ることがあります。
残ったロックは自動では外れず、次の実行でそのブックが止まります。
このツール、AI の接続先、Excel のプロセスが残っていないことを確かめてから、ロックのファイルを消します。

### 作業中のコードで実行する場合

リポジトリで `uv run` から CLI を動かすと、インストール済みの CLI ではなく、作業ツリーのコードを使います。
一括実行の途中でコードを直すと、次のブックから直したコードで動きます。
どのブックをどの版で処理したかを残す場合は、直した後に commit してから再開します。

## 処理に手間のかかるブック

数百冊を処理して見つかった、手間のかかるブックの形と、このツールでの扱いです。

| ブックの形 | 起きること | 扱い |
| --- | --- | --- |
| 描くものがない空のシート | 画像にできません。 | そのシートを `skipped` にします。異常ではありません。 |
| グラフシートなど、ワークシート以外のシート | セルがありません。 | そのシートだけを `skipped` にし、残りを続けます。 |
| 数千行のデータの表 | セルの数・文字数・画像の枚数が上限を超えます。 | 見出しと最初の10行を残し、残りを列ごとに要約します（「[長いデータの表を要約する](sheet-content.md#長いデータの表を要約する)」）。 |
| 月ごとの明細のように、短い表を題名や合計をはさんで繰り返すシート | 1つずつの表は短いため、要約しても上限を超えます。 | 繰り返す表を1つの範囲として要約します（`repeatedBlocks`）。 |
| 画面の切り抜きや図形を広い範囲に並べたシート | データの表がないため、要約しても画像が減りません。 | `max_images` を上げるか、写す範囲を広げて描き直します（`tileScale`）。 |
| 根拠データが100万文字を超えるシート | Codex CLI が入力を断ります。 | `max_input_chars` を指定し、長いデータの範囲を要約して送ります。 |
| 長いデータの表がなく、数式のセルが数千あるシート（計算の小さな表を並べたものなど） | 要約できる範囲がなく、描画で加えるセルの位置と表示文字で根拠データが増え、上限を超えることがあります。 | セルの位置と表示文字を短い形で送ります。それでも超える場合は、そのシートを飛ばします。 |
| Power Pivot のデータモデルで大きくなったブック | シートは小さくても、ファイルが数百 MB になります。 | `max_workbook_mb` を超えると、Excel で開かずに画像なしで解析します（`textOnly`）。`--cover sheet` の表紙も描かず、前の表紙を残します（表紙の結果は `warning`）。 |
| 同じ固定 ID を持つコピー（年ごとに分けたブックなど） | 同じ代理ノートを指します。 | 同期の記録にあるブックが代理ノートを引き継ぎ、ほかはコピーとして別の代理ノートを作ります。見分けられないときは `duplicate-id` で止まります（「[ブックをコピーしたとき](../reference/synchronization.md#ブックをコピーしたとき)」）。 |
| Excel で開けないブック（修復が必要なもの） | 画像化で失敗し、AI を呼ぶ前にエラーになります。 | Excel で修復して保存し直してから、やり直します。修復でシート名が `Recovered_Sheet1` などに変わることがあるため、確かめます。 |
| 列の幅が狭い方眼紙のシート | 表紙の範囲が縦に長く、画像の画素数の上限を超えます。 | 範囲を変えずに、描く幅を下げて縦長の表紙にします（「[シートの指定範囲を画像にする](catalog-operations.md#シートの指定範囲を画像にする)」）。 |
| パスワードで保護されたシート | 表紙を描くための一時的な図形を置けません。 | 表紙を描く使い捨ての写しだけ、保護を外します。元のブックは変えません。 |
| セル範囲を写す図（Excel のカメラで作るリンクされた図） | 表紙を描くための一時的な枠まで写し込みます。 | ページに直接描かれた枠で範囲を測り、写し込まれた枠も画像から消します。 |
| 描画の途中で Excel が応答しなくなるシート | まれに起きます。同じシートを描き直すと、すぐ終わることがあります。 | `max_render_seconds` を超えると、そのシートを飛ばします。 |

画像化の間、Excel のウィンドウと進捗ウィンドウは画面に表示されません（「[画像化中の進捗ウィンドウ](sheet-content.md#画像化中の進捗ウィンドウ)」）。
一括実行の間も、ほかの作業を続けられます。

## 説明の読み方

AI は、罫線、色、データバー、数式から、表の意味を読み取れることが多くあります。
図のないシートでも、セルの位置、色、罫線、列のずらし方で表や階層を表していることがあるため、説明の対象から外さないほうが、ブックの内容をつかみやすくなります。

要約したデータの表は、見出しと最初の行、列ごとの値の範囲から説明するため、個々の行の値は説明に出ません。
小さな文字や矢印の接続先は誤読されることがあります。
重要な箇所は、元のシートと見比べてください。
