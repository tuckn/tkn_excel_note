# export --context を実務で使った結果と改善の候補

2026-11-27 に、利用側のプロジェクト（非公開）で `export --context` を使った結果から、改善の候補をまとめた引き継ぎ。
顧客の資料のため、ブック名・パス・内容は書かない。

## 使い方

業務システムの設計書（Excel）を AI に読ませてレビューするため、文字の抽出だけでは入らない図・画面イメージの中身も Markdown に入れたかった。

- 版：`tkn-excel-note 5.1.0`（Windows、Excel デスクトップ版）
- コマンド（1冊ずつ）：

  ```shell
  tkn-excel-note export <book.xlsx> --context --generator copilot-high --output <book.md> --force --verbose
  ```

  元のブックの隣に書けないため、作業用のフォルダに `--output` で出した。そのため、名前が既定の `<book.xlsx>.md` にならなかった（10 を参照）。

- generator：`copilot-high`（GitHub Copilot、reasoning high）。顧客の資料なので、既定の profile でなく、作業に使っていた AI と同じものを選んだ。
- 9冊を、別々の `pwsh` で同時に実行した（`Start-Process`。ログは1冊ずつ別のファイル）。
- 修正の痕跡（取り消し線・赤字・コメント）は、`openpyxl` で別に書き出した（利用側で作った小さなスクリプト）。

## 規模と時間（ログの実測）

| 項目 | 値 |
| --- | --- |
| ブック | 9冊（同じ設計書の、変更前と変更後の版を含む） |
| シート | 1冊あたり 11〜15 |
| 所要時間 | 1冊あたり 800〜1,230 秒。画像の多い2冊（15シート、画像 87 枚と図形 12 個を含む）は 2,192 秒と 2,468 秒 |
| 出典画像 | 799 ファイル、176 MB（9冊の合計） |
| 最も大きいノート | 約 1.18 MB（約 66 万文字）。うち約 85 % が Extracted Text |
| 失敗 | 1回（後述の `local_io`）。同じコマンドをやり直して成功した |

AI の説明の質は高かった。
画面遷移図の矢印の向きや小さな文字まで読み、ほかの設計書との食い違いを「不確実な点」に挙げていた。
レビューで「要確認」にしていた 27 件のうち 21 件を、この説明と出典画像で確かめられた。

## 改善の候補

優先度は、今回の作業で困った度合いで付けた。
「現状」は確かめた事実、「案」は提案で、まだ設計していない。

### 1. 修正の痕跡（取り消し線・文字の色・コメント）を export に出す（高）

- 現状
  - `export` の Extracted Text は、セルの値・数式・図形の文字だけで、書式は出さない（`docs/reference/note-format.md` の記述どおり）。
  - 9冊のノートに `Comment at` の行は1つもなかった。一方で、同じブックを `openpyxl` で読むと、コメントのあるセルが 9〜14 個あった。どれもスレッド形式のコメント（返信付き）で、顧客の指摘と、作成者の回答が入っていた。
  - AI の説明は、画像から「赤字」に触れることはあるが、セルの一部の取り消し線や、どの文字が赤いかまでは拾えない。
- 影響
  - レビュー中の設計書では、取り消し線・赤字・コメントが「何を直したか」「顧客の指摘に回答したか」の根拠になる。今回の指摘の多くは、これを根拠にした。
  - 書式がないと、取り消し済みの古い記述と、新しい記述が区別できず、AI が古い記述を正として読むおそれがある。
- 案
  - Extracted Text に、書式の印を付けて出す選択肢（例：`~~取り消し~~`、`{color:FF0000}…{/color}`）。セル全体の書式と、セルの一部の書式（リッチテキスト）の両方。
  - 色は、テーマの色と濃淡（tint）も RGB に直して判定する。利用側のスクリプトは RGB の `FF0000`・`C00000` しか拾えず、テーマの赤を見落とした。
  - `export` でもコメントを出す。スレッド形式は、作成者・返信の順・解決済みかを残す。旧形式の注記と区別する。
  - これらを AI への根拠データにも入れ、「取り消し線の記述は削除済みとして読む」と指示する。

### 2. export でも、説明の再利用と、途中からの再開をできるようにする（高）

- 現状
  - `pull --source` は、変更のないシートの説明を再利用し、失敗したら残りのシートから続ける（`docs/guides/sheet-content.md`「source 同期での更新と再利用」）。
  - `export --force` は、毎回すべてのシートを作り直す。
  - 変更前と変更後の版で、セルの値が1つも違わないブックがあった（xlsx の部品の違いは、スクロール位置と文書プロパティだけ）。それでも 15 シートを作り直し、約 40 分かかった。
  - 作業中に SharePoint でブックが更新され、2回すべてを作り直した。
- 案
  - `export` でも、`img/` の `output.json` と生成条件が同じシートは再利用する（`pull` と同じ判定）。
  - ブックのファイルが違っても、シートの内容と描画の条件が同じなら再利用できるように、キャッシュの鍵をブックでなくシートの内容から作る。版違いのブックを並べて読ませる使い方で効く。
  - 失敗したら、成功したシートを残し、同じコマンドで続きから始める。

### 3. 大きなノートを分ける（高）

- 現状
  - 最も大きいノートは約 1.18 MB で、AI のエージェントが1回で読める量を超えた。部分ごとに読ませる必要があった。
  - その約 85 % は Extracted Text だった。説明（シート要約・内容・不確実な点）だけなら、十分に小さい。
- 案
  - 出力の分け方を選べるようにする。例：`--split sheets`（シートごとのファイルと、目次のファイル）、`--extracted-text separate`（Extracted Text を別のファイルに出し、本文からリンクする）。
  - 目次には、シートごとの文字数・画像数を載せ、どれを読むかを選びやすくする。

### 4. 一時的な失敗を自動でやり直す（中）

- 現状
  - 2シート目で、次のエラーでブック全体が止まった。同じコマンドをやり直すと成功した。

    ```text
    Bridge generation failed (local_io): provider local I/O failed; check temporary directory permissions; no automatic retry.
    ```

  - このとき、9冊を同時に動かしていた。同時の実行と関係があるかは確かめていない。
- 案
  - `local_io` など一時的なものは、シートの単位で、間を空けて数回やり直す。
  - 2 の「途中からの再開」とあわせ、やり直しても成功しなければ、成功したシートを残して止める。

### 5. 2つのブックを比べる（中）

- 現状
  - 変更前と変更後の版で、変更による誤りがないかを確かめたかった。xlsx を展開し、シートの XML を手で比べた。
  - xlsx の `sheetN.xml` とシート名の対応は、`workbook.xml` と rels で確かめる必要があり、手間がかかった。
- 案
  - `workbook diff <A> <B>` のようなコマンド（書き込みはしない）。シート名で対応させ、セルの値・数式、図形の文字、画像のハッシュ、書式の印（1 の取り消し線・色）、コメントの違いを出す。
  - 表示の状態だけの違い（スクロール位置など）は、`pull` の再利用の判定と同じく無視する。

### 6. 同時に実行するときの扱い（中）

- 現状
  - フォルダを渡すと順に処理するため、9冊を別々のプロセスで同時に動かした。
  - その後、`/automation` で起動された EXCEL.EXE が1つ残っていた。このツールのものか、利用側のスクリプトのものかは確かめていない。
- 案
  - フォルダの export に、同時に処理する数を指定する選択肢（例：`--jobs N`）。Excel のインスタンスと、AI の呼び出しの数を、ツールが管理する。
  - 終了時（異常終了を含む）に、自分が起動した Excel を終わらせることを確かめるテスト。

### 7. 説明の有無を本文にも出す（低）

- 現状
  - `--context` なしで作ったノートを、説明付きのものと取り違えかけた。区別は Frontmatter の `generationMethod: text`・`contextStatus: not-generated` にしかない。
- 案
  - `--context` なしのノートは、タイトルの下に「AI の説明はありません（文字の抽出だけ）」の1行を置く。

### 8. 出典画像を軽くする（低）

- 現状：9冊で 799 ファイル・176 MB。利用側では Git の対象外にした。
- 案
  - 画像の出力先を、ノートのフォルダの外にも指定できるようにする。
  - PNG の圧縮を強める、または縮小図と詳細のタイルのどちらを残すかを選べるようにする。

### 9. 版を決める手がかりを Frontmatter に出す（低）

- 現状
  - どれが最新かを決めるのに迷った。ファイルの更新日時は、開いて保存しただけで新しくなるため。
  - 実際には、改版履歴のシートの最後の行と、文書プロパティの最終更新者で判断した。
- 案
  - `lastModifiedBy`（docProps/core.xml）を Frontmatter に出す。
  - 改版履歴らしいシートの最後の行を拾うかどうかは、誤判定のおそれがあるので慎重に決める。

### 10. 出力先のフォルダを指定して、`<ブック名>.xlsx.md` の名前で出す（中）

- 現状
  - 既定では、ブックの隣に `<ブック名>.xlsx.md` を出す。利用者は、この名前を望んでいる。どの形式から作ったノートかが、名前で分かるため。
  - 今回は、元のブック（SharePoint の同期フォルダ。メンバーが編集中）の隣に書けなかった。そのため、作業用のフォルダに同じフォルダ構成で出したかった。
  - しかし `--output` は1冊だけにしか使えないため、1冊ずつ `--output` を指定した。その結果、名前が `<ブック名>.md` になり、既定の名前とそろわなかった。
- 案
  - フォルダの export に、出力先のフォルダを指定する選択肢（例：`--output-dir <dir>`）を足す。入力フォルダからの相対パスを保ち、名前は既定と同じ `<ブック名>.xlsx.md` にする。`img/` も、出力先のノートの隣に置く。
  - `--output` で、`.xlsx.md` で終わらない名前を指定したときは、警告するかを検討する。

### 11. 表を、Markdown の表として再現する（高）

- 現状
  - 要件の対応表のシートがあった。題名と説明の下に、Excel のテーブル（ListObject）として定義した表（4列・約115行。結合セルなし）がある。
  - Extracted Text では、この表もセル1つにつき1行（`- B5: … | C5: …` の形）で出る。行と列の対応を読み取りにくく、量も増える。
  - AI の説明は、表の中身を独自の略記（「管理3項目」など）にまとめて書き換えた。要件と参照先を1件ずつ突き合わせるレビューでは、元の文字が失われるのは危険である。
  - Workbook Map は Excel のテーブルの数を数えているので、範囲と列名はすでに取れている。長い表の要約（`docs/guides/sheet-content.md`「長いデータの表を要約する」）は AI への入力を短くするためのもので、ノートに表としては出さない。
- 案：確かなものから順に表にする
  1. Excel のテーブル：必ず表にする。見出しはテーブルの列名を使う。AI も推定も使わない。
  2. 見た目だけの表：見出しの行と、同じ列が埋まった行が続く範囲を表にする。長い表の要約の範囲の判定を流用する。判定に自信があるときだけ表にする。
  3. 複雑な配置（帳票の形、表の中の表など）：今のとおり、セルの位置付きで出す。
- 出し方の注意
  - 場所の手がかりを残す：表の範囲（例：`B4:E119`）を見出しに書き、行番号の列を付ける。レビューでセルを示すのに要る。
  - セルの中の改行は `<br>` にし、`|` はエスケープする。
  - 修正の痕跡（取り消し線・赤字。1 を参照）の印は、セルの中に残す。
  - 縦に結合したセルは、値を下の行にも繰り返すか、空けるかを選べるようにする。
  - 見出しが2段以上の表は、見出しを「上段 / 下段」のようにつなぐ。
  - 表にした範囲は、Extracted Text の座標の行から外す。重複がなくなり、ノートも小さくなる（3 の対策にもなる）。表の外のセル（題名・説明など）は、今の形で残す。
  - AI への根拠データにも表として渡し、「表の中身は本文にそのまま載っているので、言い換えずに、要約と気づいたことだけを書く」と指示する。
  - Extracted Text は、push で読まない管理領域のままにする。表にしても、Markdown から Excel へ書き戻す対象にはしない。
- 確かめ方：対象の表で、行数・列数・各セルの値が元のブックと一致するか。結合セル・改行・`|` を含むセルで崩れないか。

### 12. 細かいこと（低）

- `export` のログの集計行が `AI pull: result=…` と出る。`export` と分かる表記がよい。
- `copilot-high` では、トークン数が `unknown` になった。GenAI Bridge が、この接続先の使用量を受け取れていないと思われる。

## 確かめていないこと

- `pull` の Extracted Text は、スレッド形式のコメント（返信）を出すか。`export` に入れるときの形を決める前に確かめる。
- AI の説明の記述が、どのセル範囲を根拠にしているか。レビューで引くときにシート名とセル番地が要ったが、説明に番地があるかどうかは、シートによって違った。
- プロジェクトのフォルダに置いた設定ファイル（`generation.default_generator`）を `export` が読むか。読むなら、毎回の `--generator` は要らない。
- `local_io` の原因（一時フォルダ、同時の実行、GitHub Copilot 側）。
